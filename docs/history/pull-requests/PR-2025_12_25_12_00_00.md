# PR-2025_12_25_12_00_00: Major Refactoring - Improve Hooks, Add Custom Hydrators, Add Logger

**Author:** Kassko 
**Date:** 2025-12-25  
**Type:** Major Refactoring  
**Breaking Changes:** Yes  
**Branch:** 2.0-alpha

## Summary

This PR implements a comprehensive refactoring of the data-mapper library with the following major changes:

1. **PSR-3 Logger Support** - Added logging capabilities for missing data keys
2. **Missing Raw Data Key Handling** - Log warnings when expected keys are absent
3. **Field Attribute Removal** - Removed deprecated `Field` attribute (use `Property`)
4. **PropertyCandidate Scope Fix** - No longer a standalone attribute
5. **MultiPropDataSource on Properties** - Now allowed directly on properties
6. **Hook System Refactoring** - Replaced single `Hook` attribute with three specialized hooks
7. **Custom Hydrators** - New system for custom hydration logic
8. **PR History File Renaming** - Timestamped format for better organization

**Important:** PHP 8.1+ required. Breaking changes with no backward compatibility.

## Changes

### 1. PSR-3 Logger Support

#### Added Logger to DataMapperBuilder

```php
use Psr\Log\LoggerInterface;

$builder = new DataMapperBuilder();
$builder->setLogger($logger);  // PSR-3 LoggerInterface
$mapper = $builder->build();
```

#### Logger Features
- Logs warnings when raw data keys are missing during hydration
- Uses PSR-3 standard logger interface
- Falls back to `NullLogger` if no logger provided
- Contextual logging with class name, property name, and expected key

#### Example Log Entry
```
[warning] Missing raw data key for property hydration
Context: {
    "class": "App\\Entity\\User",
    "property": "email",
    "expected_key": "user_email"
}
```

### 2. Missing Raw Data Key Handling

Previously, when a property's corresponding data key was missing, the hydration would silently skip the property. Now:

- Missing keys are logged at `warning` level
- Hydration still skips the property (no exception thrown)
- Provides visibility into data integrity issues
- Helps debug mapping mismatches

### 3. Field Attribute Removal

**BREAKING CHANGE**

The `Field` attribute has been completely removed. Use `Property` instead.

**Before (OLD - No longer works):**
```php
use Kassko\DataMapper\Attribute\Field;

class User
{
    #[Field('user_name')]
    private string $username;
}
```

**After (NEW):**
```php
use Kassko\DataMapper\Attribute\Property;

class User
{
    #[Property(name: 'user_name')]
    private string $username;
}
```

**Migration Guide:**
- Replace `#[Field('name')]` with `#[Property(name: 'name')]`
- Update all imports from `Field` to `Property`
- `Property` provides additional features like `class`, `expand`, `noExpand`, `mapping`

### 4. PropertyCandidate Scope Fix

**BREAKING CHANGE**

`PropertyCandidate` is now only usable inside `PropertyCandidates` attribute. It cannot be used directly on a property.

**Before (INVALID - Never worked correctly):**
```php
#[PropertyCandidate(...)]  // ERROR!
private $property;
```

**After (CORRECT):**
```php
use Kassko\DataMapper\Attribute\PropertyCandidates;
use Kassko\DataMapper\Attribute\PropertyCandidate;
use Kassko\DataMapper\Attribute\Property;

#[PropertyCandidates([
    new PropertyCandidate(
        discriminator: "expr(rawDataItemExists('type_a'))",
        property: new Property(class: TypeA::class)
    ),
    new PropertyCandidate(
        discriminator: "expr(rawDataItemExists('type_b'))",
        property: new Property(class: TypeB::class)
    )
])]
private $property;
```

**Changes:**
- Removed `#[Attribute(Attribute::TARGET_PROPERTY)]` from `PropertyCandidate`
- `PropertyCandidate` is now a plain class used as a value object
- Must be instantiated within `PropertyCandidates` array

### 5. MultiPropDataSource on Properties

**NEW FEATURE**

`MultiPropDataSource` can now be used on properties in addition to classes and DataSourcesStore.

**Before (Still works):**
```php
#[DataSourcesStore([
    new MultiPropDataSource(id: 'user_data', class: UserDS::class, method: 'getData')
])]
class User
{
    #[DataSourceRef(id: 'user_data')]
    private $name;
}

// OR on class
#[MultiPropDataSource(id: 'user_data', class: UserDS::class, method: 'getData')]
class User
{
    #[DataSourceRef(id: 'user_data')]
    private $name;
}
```

**After (NEW - Also works):**
```php
class User
{
    #[MultiPropDataSource(class: UserDataSource::class, method: 'getData')]
    private $userData;
}
```

**Changes:**
- Added `Attribute::TARGET_PROPERTY` to `MultiPropDataSource`
- Now supports three usage patterns:
  - Inside `DataSourcesStore` (with `id`)
  - On classes (with `id`, for shared data sources)
  - On properties (for property-specific multi-value hydration)
- Updated documentation to reflect all usage patterns

### 6. Hook System Refactoring

**BREAKING CHANGE**

Replaced the single `Hook` attribute with three specialized hook attributes:

#### 6.1 PropertySettingHook (Property-level)

Replaces `Hook` with `name: 'before_set_property'` and `name: 'after_set_property'`.

**Before (OLD):**
```php
use Kassko\DataMapper\Attribute\Hook;

class Person
{
    #[Hook(name: 'before_set_property', method: 'validate', args: ['#firstName'])]
    #[Hook(name: 'after_set_property', method: 'onChange', args: ['##object'])]
    private $firstName;
}
```

**After (NEW):**
```php
use Kassko\DataMapper\Attribute\PropertySettingHook;

class Person
{
    #[PropertySettingHook(
        before_set_property: 'validate',
        after_set_property: 'onChange',
        args: ['#firstName']
    )]
    private $firstName;
}
```

**Features:**
- Can specify both `before_set_property` and `after_set_property` in same attribute
- Executed during property value assignment
- Supports external service classes via `class` parameter

#### 6.2 PropertyInstantiatingHook (Class-level)

Replaces `Hook` with `name: 'after_create_object'`.

**Before (OLD):**
```php
use Kassko\DataMapper\Attribute\Hook;

#[Hook(name: 'after_create_object', method: 'initialize', args: ['##object'])]
class Entity
{
    public function initialize(self $obj): void {
        // Init logic
    }
}
```

**After (NEW):**
```php
use Kassko\DataMapper\Attribute\PropertyInstantiatingHook;

#[PropertyInstantiatingHook(after_instantiating: 'initialize', args: ['##object'])]
class Entity
{
    public function initialize(self $obj): void {
        // Init logic
    }
}
```

**Features:**
- Clearer naming: `after_instantiating` instead of `after_create_object`
- Executed immediately after `new ClassName()`
- Before any property hydration begins

#### 6.3 PropertyHydratingHook (Class-level)

**NEW ATTRIBUTE** for object-level hydration hooks.

```php
use Kassko\DataMapper\Attribute\PropertyHydratingHook;

#[PropertyHydratingHook(
    before_hydrate_object: 'prepare',
    after_hydrate_object: 'finalize'
)]
class Entity
{
    public function prepare(array $rawData): void {
        // Called before hydration starts
    }
    
    public function finalize(?object $object, array $rawData): void {
        // Called after hydration completes
        // $object can be null if custom hydrator returned null
    }
}
```

**Features:**
- `before_hydrate_object`: Called before any properties are set
- `after_hydrate_object`: Called after all properties are set
- Signature for `before_hydrate_object`: `(array $rawData)`
- Signature for `after_hydrate_object`: `(?object $object, array $rawData)`
- Executed after instantiation but during hydration process

**Hook Execution Order:**
1. Object instantiated
2. `PropertyInstantiatingHook::after_instantiating`
3. `PropertyHydratingHook::before_hydrate_object`
4. Individual properties hydrated (with `PropertySettingHook` before/after)
5. `PropertyHydratingHook::after_hydrate_object`

#### 6.4 Hook Attribute Removal

The generic `Hook` attribute has been completely removed:
- `src/Attribute/Hook.php` - DELETED
- All uses migrated to specialized hooks
- Test fixtures updated

**Migration Summary:**
| Old Hook | New Attribute |
|----------|---------------|
| `Hook(name: 'after_create_object', ...)` | `PropertyInstantiatingHook(after_instantiating: ...)` |
| `Hook(name: 'before_set_property', ...)` | `PropertySettingHook(before_set_property: ...)` |
| `Hook(name: 'after_set_property', ...)` | `PropertySettingHook(after_set_property: ...)` |
| N/A | `PropertyHydratingHook(before_hydrate_object: ...)` (NEW) |
| N/A | `PropertyHydratingHook(after_hydrate_object: ...)` (NEW) |

### 7. Custom Hydrators

**NEW FEATURE**

Added support for custom hydration logic via the `CustomHydrator` attribute.

#### 7.1 CustomHydrator Attribute

```php
use Kassko\DataMapper\Attribute\CustomHydrator;

class Document
{
    #[CustomHydrator(
        key: 'complex_parser',
        objectClass: ContentInterface::class  // Optional type validation
    )]
    private ?ContentInterface $content = null;
}
```

**Parameters:**
- `key` (string): Identifier for the custom hydrator
- `objectClass` (string|null): Optional class for return type validation

#### 7.2 Registering Custom Hydrators

```php
$builder = new DataMapperBuilder();

$builder->addCustomHydrator('complex_parser', function(array $data): ?object {
    return match($data['type'] ?? null) {
        'text' => new TextContent($data),
        'html' => new HtmlContent($data),
        'markdown' => new MarkdownContent($data),
        default => null,
    };
});

$mapper = $builder->build();
```

**Hydrator Signature:**
```php
function(array $data): ?object
```

#### 7.3 Attribute Exclusivity Validation

`CustomHydrator` **cannot** be combined with:
- `Property`
- `PropertyCandidates`
- `DataSource`
- `DataSourceRef`
- `SinglePropDataSource`
- `MultiPropDataSource`

**Attempting to combine throws `InvalidArgumentException`:**
```php
// INVALID - Throws exception!
#[CustomHydrator(key: 'parser')]
#[Property(class: User::class)]  // Conflict!
private $user;
```

**Validation happens at runtime when property is loaded.**

#### 7.4 Use Cases

1. **Complex Type Discrimination**
   - Beyond what `PropertyCandidates` can handle
   - Multiple factors determining type

2. **Third-Party Object Construction**
   - When you can't control object instantiation
   - Factory pattern objects

3. **Legacy Data Migration**
   - Handling multiple legacy formats
   - Complex transformations

4. **Custom Validation**
   - Validate and transform in one step
   - Return null to skip hydration

#### 7.5 Known Limitation: Loading Attribute

The `Loading` attribute (for depth control) may not work correctly with `CustomHydrator` because:
- Custom hydrators control the entire hydration process
- Depth management must be implemented inside the hydrator
- This is an **accepted limitation** for v2.0

If depth control is needed, implement it within your custom hydrator callable.
