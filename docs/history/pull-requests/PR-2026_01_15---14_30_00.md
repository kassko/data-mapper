# PR: Fix Naming Convention Auto-Detection in Recursive Hydration

**Date**: 2026-01-15  
**Branch**: `fix/code/mapping`  
**Type**: Bug Fix / Enhancement

## Summary

This PR fixes a bug where recursive hydration of nested objects failed when raw data keys used a different naming convention (e.g., `snake_case`) than PHP properties (e.g., `camelCase`).

## Problem

When hydrating nested objects recursively, the system would:
1. Take a property name like `firstName`
2. Look for a key `firstName` in the raw data
3. Fail to find it because the raw data used `first_name`
4. Skip the property, causing nested object hydration to fail

This was particularly problematic for arrays of nested objects where no explicit `sourceField` mapping was configured.

## Solution

### 1. PropertyMappingRegistry (New)

Created a new registry (`src/Registry/PropertyMappingRegistry.php`) that uses `WeakMap` to store bidirectional mappings between:
- Property names (PHP side) → Source field names (raw data side)
- Source field names → Property names

This allows looking up the correspondence in both directions.

### 2. Automatic Naming Convention Detection

Added methods in `Loader.php` to automatically detect and convert between naming conventions:

- `camelToSnake()`: Converts `firstName` → `first_name`
- `snakeToCamel()`: Converts `first_name` → `firstName`
- `findMatchingFieldInData()`: Tries to find a matching key in raw data using:
  1. Exact match with property name
  2. Snake case conversion
  3. Camel case conversion
- `getSourceFieldNameWithData()`: Gets the source field name with automatic detection and registers the mapping

### 3. Updated Hydration Methods

Modified the following methods to use the new auto-detection logic:
- `hydrateProperty()`: For single property hydration from array data
- `hydrateObject()`: For full object hydration (used in recursive hydration)
- `hydrateFromDto()`: For DTO-based hydration

### 4. Priority Rules

The system respects the following priority:
1. **Explicit `sourceField`**: If defined via `#[Property(sourceField: 'xxx')]`, always use it
2. **Exact match**: If raw data contains an exact key matching the property name
3. **Snake case conversion**: Try `firstName` → `first_name`
4. **Camel case conversion**: Try `first_name` → `firstName`

## Usage Example

```php
// Raw data with snake_case keys
$rawData = [
    'company_name' => 'ACME Corp',
    'employees' => [
        ['first_name' => 'John', 'last_name' => 'Doe'],
        ['first_name' => 'Jane', 'last_name' => 'Smith'],
    ],
];

// Model with camelCase properties - NO explicit sourceField needed!
class Company {
    public string $companyName;  // Auto-maps to 'company_name'
    
    #[Property(class: Employee::class)]
    public array $employees;
}

class Employee {
    public string $firstName;   // Auto-maps to 'first_name'
    public string $lastName;    // Auto-maps to 'last_name'
}

$company = $hydrator->hydrate(Company::class, $rawData);
// Works! All properties are correctly hydrated.
```
