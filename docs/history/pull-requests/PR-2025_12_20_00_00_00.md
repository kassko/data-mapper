# PR-0017: DataSource Improvements, Property Locking, and Expression Language Enhancements

**Date:** 2025-12-20  
**Type:** Enhancement  
**Breaking Changes:** Yes

## Summary

This PR implements 5 major improvements to the data-mapper library:

1. Fixed DataSource scope rules (breaking change)
2. Added property locking mechanism
3. Enhanced expression language with `_this()` and parent access
4. Clarified PropertyCandidates documentation
5. Updated all related documentation

**Important:** PHP 8.1+ required. No backward compatibility for scope changes - breaking changes are acceptable.

## Changes

### 1. DataSource Scope Fixes

#### MultiPropDataSource
- **Breaking**: Removed `Attribute::TARGET_CLASS` and `Attribute::IS_REPEATABLE`
- Now ONLY usable inside `DataSourcesStore`
- Cannot be used as standalone attribute on classes
- Multiple instances must be grouped in single `DataSourcesStore`

```php
// Before (OLD - No longer works)
#[MultiPropDataSource(id: 'source1', ...)]
#[MultiPropDataSource(id: 'source2', ...)]
class Person { }

// After (NEW - Required)
#[DataSourcesStore([
    new MultiPropDataSource(id: 'source1', ...),
    new MultiPropDataSource(id: 'source2', ...),
])]
class Person { }
```

#### SinglePropDataSource
- **Breaking**: Removed `Attribute::IS_REPEATABLE`
- Can still be used on properties or in `DataSourcesStore`

#### DataSourcesStore
- Now accepts `MultiPropDataSource` in addition to `SinglePropDataSource` and `DataSource`
- Updated type signature: `array<SinglePropDataSource|DataSource|MultiPropDataSource>`

### 2. Property Lock/Unlock Mechanism

Added locking mechanism to `LoadableTrait` to prevent lazy/eager loading from modifying property values.

**New Methods:**
- `lockProperty(string $propertyName): void` - Locks a property
- `unlockProperty(string $propertyName): void` - Unlocks a property
- `isPropertyLocked(string $propertyName): bool` - Checks lock status

**LazyLoader Integration:**
- Checks `isPropertyLocked()` before hydrating
- Skips loading if property is locked
- Manual setters still work

**Example:**
```php
class Person
{
    use LoadableTrait;
    
    public function setFirstName(string $value): void
    {
        $this->firstName = $value;
        $this->lockProperty('firstName');  // Prevent lazy loading from overwriting
    }
}
```

**Accessibility:**
- Lock/unlock methods are `protected` (accessible in child classes)
- `isPropertyLocked()` is `public` (checked by LazyLoader)

### 3. Expression Language Enrichment

#### Renamed `_self()` to `_this()`
- New preferred name: `_this()`
- Old name `_self()` kept for backward compatibility
- Both return the current object being hydrated

```php
// New (preferred)
args: ["expr(_this())"]

// Old (still works)
args: ["expr(_self())"]
```

#### Added `thisParent()` Function
Returns the parent object (the object that contains the current object). Returns `null` if no parent.

```php
args: ["expr(thisParent())"]
```

#### Added `#parent` Expression
Simple expression equivalent of `thisParent()`:

```php
args: ["#parent"]
args: ["##parent"]  // Also works
```

#### Parent Tracking Implementation
- Added `WeakMap $parentRegistry` to `LazyLoader`
- Tracks parent-child relationships during recursive hydration
- `getParentObject(object $object): ?object` method added
- Parent tracking happens in `applyRecursiveHydration()`

### 4. PropertyCandidates Documentation Clarification

Updated documentation to clarify that `PropertyCandidates` is NOT just for polymorphism.

**Use Cases Documented:**
- **Polymorphism** - Different class based on data type
- **Data-driven** - Configuration based on other property values (`#isPremium`)
- **Environment** - Different behavior for `envVar('APP_ENV')`
- **Context** - Based on `context('tenant_type')`
- **Runtime state** - Any runtime condition

## Migration Guide

### Migrating MultiPropDataSource Usage

**Before:**
```php
#[MultiPropDataSource(id: 'source1', class: Service::class, method: 'get')]
#[MultiPropDataSource(id: 'source2', class: Service::class, method: 'get')]
class Person { }
```

**After:**
```php
#[DataSourcesStore([
    new MultiPropDataSource(id: 'source1', class: Service::class, method: 'get'),
    new MultiPropDataSource(id: 'source2', class: Service::class, method: 'get'),
])]
class Person { }
```

**Important:**
- Add `use Kassko\DataMapper\Attribute\DataSourcesStore;`
- Wrap all `MultiPropDataSource` instances in `DataSourcesStore`
- Use `new MultiPropDataSource(...)` instead of `#[MultiPropDataSource(...)]`

### Using Property Locking

```php
use Kassko\DataMapper\ObjectExtension\LoadableTrait;

class Person
{
    use LoadableTrait;
    
    private ?string $value = null;
    
    public function setValue(string $val): void
    {
        $this->value = $val;
        $this->lockProperty('value');  // Lock to prevent reload
    }
    
    public function reset(): void
    {
        $this->unlockProperty('value');
        $this->value = null;
    }
}
```

### Using New Expression Features

```php
// Use _this() instead of _self()
#[DataSourcesStore([
    new SinglePropDataSource(id: 'processor', class: Service::class, method: 'process', args: ['expr(_this())']),
])]

// Access parent object
args: ['#parent']  // Simple expression
args: ['expr(thisParent())']  // Function call
```

## Breaking Changes

1. **MultiPropDataSource** can no longer be used as a standalone class attribute
2. **MultiPropDataSource** is no longer repeatable
3. **SinglePropDataSource** is no longer repeatable
4. All existing code using multiple `#[MultiPropDataSource]` must be updated to use `DataSourcesStore`
