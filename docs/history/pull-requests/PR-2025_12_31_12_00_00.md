# PR: PHP 8 Attribute Cascading from Parent Classes and Traits

## Summary

This PR implements full PHP 8 attribute cascading support for `DataSourcesStore` and `PropertyConfigStore` attributes, allowing child classes to inherit and reference configurations defined in parent classes and traits.

## Motivation

When building complex data object hierarchies, it's common to want to:
- Define shared data sources in a base class or trait
- Reference those data sources from child classes
- Override specific configurations when needed

Previously, DataMapper only looked at attributes on the current class, requiring duplication of `DataSourcesStore` and `PropertyConfigStore` definitions.

## Changes

### New Features

#### Attribute Cascading
- **DataSourcesStore cascading**: Child classes now inherit all DataSources from parent classes and traits
- **PropertyConfigStore cascading**: Child classes now inherit all PropertyConfigs from parent classes and traits
- **Conflict resolution**: When the same ID is defined in multiple places, the child's definition takes precedence
- **Property attribute override detection**: When a child shadows a parent's private property with its own, the child's attributes are used exclusively

#### Logging and Collection
- New `AttributeCascadeCollector` class to track cascading events
- New `CascadeEvent` class representing individual cascade events
- Events are logged at INFO level for merges, WARNING level for conflicts
- Collector provides summary statistics for debugging

### Implementation Details

#### AttributeReader Changes
- Added `readCascadedDataSourcesStore()` method for full hierarchy traversal
- Added `readCascadedPropertyConfigStore()` method for full hierarchy traversal
- Updated `getDataSourceMap()` to use cascaded version automatically

- Added recursive trait collection methods

#### Loader Changes
- Added `AttributeCascadeCollector` dependency
- Updated to use cascaded `PropertyConfigStore` for polymorphic hydration
- New `getCascadeCollector()` method for accessing collector

## Breaking Changes

None. This is a backward-compatible addition. Existing code that doesn't use inheritance continues to work unchanged.

## Event Types

| Event Type | Severity | Description |
|------------|----------|-------------|
| `TYPE_DATASOURCES_STORE_MERGE` | Info | DataSourcesStore merged from parent/trait |
| `TYPE_PROPERTY_CONFIG_STORE_MERGE` | Info | PropertyConfigStore merged from parent/trait |
| `TYPE_DATASOURCE_ID_CONFLICT` | Warning | DataSource ID overridden by child |
| `TYPE_PROPERTY_CONFIG_ID_CONFLICT` | Warning | PropertyConfig ID overridden by child |
| `TYPE_PROPERTY_ATTRIBUTE_OVERRIDE` | Warning | Property attributes shadowed by child |

## Usage Example

```php
// Parent class defines data sources
#[DataSourcesStore([
    new SinglePropDataSource(id: 'parentSource', class: ParentDataSource::class, method: 'getData'),
])]
abstract class BaseEntity {}

// Trait defines additional data sources
#[DataSourcesStore([
    new SinglePropDataSource(id: 'traitSource', class: TraitDataSource::class, method: 'getData'),
])]
trait DataSourceTrait {}

// Child class inherits both and can add its own
class ChildEntity extends BaseEntity
{
    use DataSourceTrait;
    
    #[DataSourceRef(id: 'parentSource')] // Reference parent's source - works!
    private ?string $fromParent = null;
    
    #[DataSourceRef(id: 'traitSource')] // Reference trait's source - works!
    private ?string $fromTrait = null;
}
```
