# PR: Complete Test Fixtures Decentralization

## Description

This PR completes the reorganization of test fixtures by eliminating all centralized fixtures and moving them to local directories for each test case.

## Changes Overview

### Test Structure Reorganization

#### Integration Tests (`tests/Integration/`)

The integration tests have been reorganized into semantic categories with local fixtures:

- **Attributes/** - Tests for PHP attributes functionality
  - `DataSourceRef_Providers/` - DataSourceRef with providers
  - `DataSourceStore/` - DataSourcesStore attribute
  - `DataSource_Chain/` - DataSource chaining
  - `DataSource_LoadingScope/` - Loading scope configurations
  - `Hook/` - Property setting/instantiating hooks
  - `Hook_ExternalService/` - Hooks with external services
  - `Keep_Skip_KeepAll_SkipAll/` - Property inclusion/exclusion
  - `Loading_Depth/` - Recursive loading depth control
  - `Loading_Eager/` - Eager loading configuration
  - `MultiPropDataSource/` - Multi-property data sources
  - `Property_ConfigCandidates/` - Property configuration candidates
  - `Property_ExpandNoExpand/` - Property expand/no-expand behavior
  - `Property_Mapping/` - Property name mapping

- **Classes/** - Tests for core classes
  - `DataMapper/` - Main DataMapper class tests
  - `ServiceLocator/` - ServiceLocator tests

- **Features/** - Tests for major features
  - `AttributeCascade/` - Attribute inheritance/cascade
  - `CustomHydrator/` - Custom hydrator implementation
  - `DifferentSignatures/` - Various method signatures support
  - `ExpressionLanguage/` - Expression language integration
  - `ParentClassHydration/` - Parent class property hydration
  - `Priority/` - DataSource priority handling
  - `RecursiveHydration/` - Recursive object hydration
  - `Registry/` - Loader registry functionality
  - `TraitHydration/` - Trait property hydration

- **Traits/** - Tests for trait functionality

- **UseCases/** - Real-world use case tests

#### Unit Tests (`tests/Unit/`)

The unit tests have also been reorganized with local fixtures:

- `AttributeReader/` - AttributeReader class tests
- `Hydrator/` - Hydrator class tests
- `Loader/` - Loader class tests
- `LoaderValidation/` - Loader validation tests
- `Attribute/` - Attribute-related unit tests
- `DataCollector/` - DataCollector unit tests
- `Expression/` - Expression parser unit tests
- `Registry/` - Registry unit tests

### Autoloading Configuration

The `composer.json` has been updated with PSR-4 namespace mappings for each local fixtures directory:

```json
"autoload-dev": {
    "psr-4": {
        "Kassko\\Sample\\AttributeReader\\": "tests/Unit/AttributeReader/Fixtures/",
        "Kassko\\Sample\\Hydrator\\": "tests/Unit/Hydrator/Fixtures/",
        "Kassko\\Sample\\Loader\\": "tests/Unit/Loader/Fixtures/",
        "Kassko\\Sample\\LoaderValidation\\": "tests/Unit/LoaderValidation/Fixtures/",
        "Kassko\\Sample\\DataSourceRefProviders\\": "tests/Integration/Attributes/DataSourceRef_Providers/Fixtures/",
        "Kassko\\Sample\\DataSourceStore\\": "tests/Integration/Attributes/DataSourceStore/Fixtures/",
        ... (32 namespace mappings total)
    }
}
```

### Key Benefits

1. **Self-contained tests**: Each test case has its own fixtures, making it easy to understand what each test needs
2. **No hidden dependencies**: It's clear which fixtures are used by each test
3. **Independent evolution**: Fixtures can be modified without affecting other tests
4. **Better maintainability**: Changes to one test don't risk breaking others

### Removed

- `tests/Fixtures/` - The entire centralized fixtures directory has been removed

## Migration Notes

- Each test category now uses a unique namespace for its fixtures (e.g., `Kassko\Sample\Hook\`, `Kassko\Sample\DataSourceStore\`)
- Tests import their fixtures from local directories instead of the centralized location
- Duplicate fixtures are intentional - each test has its own independent copy
