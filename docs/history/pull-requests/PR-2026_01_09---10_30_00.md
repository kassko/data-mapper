# PR: Key Renaming, HandleProperty Effect on DataSources, and Loading Scope Behavior

## Summary

This PR introduces breaking changes focused on three main areas:
1. Renaming `Property::key` and `PropertyConfig::key` to `sourceField` for better semantics
2. Enforcing MultiPropDataSource uniqueness per class
3. Making HandleProperty pattern exclusively control data source loading
4. Improving MultiPropDataSource loading scope behavior

## Changes

### 1. Renamed `Property::key` to `Property::sourceField`

**Reason**: The parameter `key` implied an array key, but in future versions we will support data sources that return DTOs. The term `sourceField` is more generic and applies to both array keys and DTO properties.

**Before:**
```php
class Person
{
    #[Property(key: 'first_name')]
    private ?string $firstName = null;
}
```

**After:**
```php
class Person
{
    #[Property(sourceField: 'first_name')]
    private ?string $firstName = null;
}
```

### 2. Renamed `PropertyConfig::key` to `PropertyConfig::sourceField`

Same rationale as above.

**Before:**
```php
new PropertyConfig(id: 'config1', key: 'some_field')
```

**After:**
```php
new PropertyConfig(id: 'config1', sourceField: 'some_field')
```

### 3. MultiPropDataSource Uniqueness Validation

Multiple properties can no longer declare MultiPropDataSource with the same ID, either directly or via DataSourceRef.

**Forbidden (will trigger validation error):**
```php
class Person
{
    #[MultiPropDataSource(id: 'personData', class: PersonRepository::class, method: 'findById', args: ['#id'])]
    private ?string $firstName = null;
    
    #[MultiPropDataSource(id: 'personData', class: PersonRepository::class, method: 'findById', args: ['#id'])]
    private ?string $lastName = null;  // ERROR: duplicate id
}
```

**Also forbidden:**
```php
#[DataSourcesStore([
    new MultiPropDataSource(id: 'personData', class: PersonRepository::class, method: 'findById', args: ['#id']),
])]
class Person
{
    #[DataSourceRef(id: 'personData')]
    private ?string $firstName = null;
    
    #[DataSourceRef(id: 'personData')]
    private ?string $lastName = null;  // ERROR: same MultiPropDataSource referenced twice
}
```

### 4. HandleProperty Pattern Exclusively Controls DataSource Loading

The HandleProperty pattern now exclusively controls whether properties with DataSource/MultiPropDataSource/DataSourceRef attributes are loaded. Previously, having a DataSource attribute was sufficient for loading.

**New behavior:** A property with a DataSource attribute will only be loaded if:
- The property is enabled
- The property resolves to `true` via HandleProperty/HandleAllProperties/when expressions

**Example - NOT loaded:**
```php
#[HandleAllProperties(value: false)]
class Person
{
    #[MultiPropDataSource(id: 'personData', class: PersonRepository::class, method: 'findById', args: ['#id'])]
    private ?string $firstName = null;  // Will NOT be loaded - no HandleProperty(true)
}
```

**Example - loaded:**
```php
#[HandleAllProperties(value: false)]
class Person
{
    #[HandleProperty(value: true)]  // Explicitly marked
    #[MultiPropDataSource(id: 'personData', class: PersonRepository::class, method: 'findById', args: ['#id'])]
    private ?string $firstName = null;  // Will be loaded
}
```

Properties with DataSource attributes that are not "handled" will generate warning logs and profiler events.

### 5. MultiPropDataSource Loading Scope Behavior

Improved the loading scope behavior for MultiPropDataSource. A property can be loaded from a MultiPropDataSource if:
- A: Property is enabled
- B: Property is authorized by the HandleProperty pattern
- C: Property name matches a key in the returned data, OR
- D: Property's `sourceField` mapping matches a key in the data
- E: Loading scope does not contradict loading this property

Formula: `A && B && (C || D) && E`

## Breaking Changes

All changes in this PR are breaking:

1. **`Property::key` → `Property::sourceField`**: Update all usages
2. **`PropertyConfig::key` → `PropertyConfig::sourceField`**: Update all usages
3. **MultiPropDataSource uniqueness**: Each MultiPropDataSource ID can only be used once per class
4. **HandleProperty controls DataSource loading**: Properties with DataSource attributes must now be explicitly "handled" to be loaded

## Migration Guide

### Rename key to sourceField

Find and replace in your codebase:
- `Property(key:` → `Property(sourceField:`
- `PropertyConfig(key:` → `PropertyConfig(sourceField:`

### MultiPropDataSource Uniqueness

If you have multiple properties referencing the same MultiPropDataSource, restructure your data sources:
- Use different MultiPropDataSource IDs for different logical data operations
- Or consolidate into a single property that receives all data

### HandleProperty Requirement for DataSources

If you use `HandleAllProperties(value: false)`, ensure all properties with DataSource attributes have:
```php
#[HandleProperty(value: true)]
```
