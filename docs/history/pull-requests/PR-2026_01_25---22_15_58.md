# PR: Fix Loading::depth attribute - read from root property

**Date**: 2026-01-25
**Branch**: `fix/code/loading_depth`
**Status**: Ready for review

## Summary

Fixed a bug where `Loading::depth` was always null because the depth value was being read from the current property being hydrated, rather than from the root property that triggered the loading.

## Problem

When using `Loading::depth` to limit recursive hydration depth, the depth limit was never applied because:

1. The `applyRecursiveHydration` method read `Loading::depth` from the current property being processed
2. Nested properties (e.g., Team inside Department) don't have a `Loading` attribute
3. Therefore, `depth` was always `null` for nested properties, meaning no limit was applied

## Solution

### Approach: Contextual Property

Store the depth limit from the root property in a contextual property `$currentDepthLimit` that persists across the recursive hydration chain.

### Implementation Details

1. **New enum `HydrationResult::Skip`**: Sentinel value to signal "don't call setter"
   - When depth is exceeded, we can't pass the raw array to a typed setter
   - Returning `HydrationResult::Skip` tells the caller to skip the setter entirely

2. **Store depth limit in `loadProperty`** (not `loadSingleProperty`):
   - Read `Loading::depth` from the property being loaded
   - Store in `$this->currentDepthLimit` before calling any loading variation
   - Use try/finally to restore previous value after completion (supports nested loading)
   - This ensures ALL loading variations respect depth: `loadSingleProperty`, `loadMultipleProperties`, `loadPropertyWithFallbacks`, `loadPropertyWithCandidates`, `loadPropertyWithProviders`

3. **Extract loading logic to `doLoadProperty`**:
   - Refactored `loadProperty` to set up depth context, then delegate to `doLoadProperty`
   - `doLoadProperty` contains the actual loading logic for all variations

4. **Check depth in `applyRecursiveHydration`**:
   - Moved depth check AFTER scalar detection (scalars are always hydrated)
   - Return `HydrationResult::Skip` when `$currentDepth > $this->currentDepthLimit`
   - All call sites updated to handle `HydrationResult::Skip`

## Depth Semantics

| Depth Value | Behavior |
|-------------|----------|
| `null` | No limit - hydrate all nested levels |
| `0` | Hydrate only the root object's scalar properties |
| `1` | Hydrate root + direct child objects |
| `N` | Hydrate N levels deep |
