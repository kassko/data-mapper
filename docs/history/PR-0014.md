## 1. Fix Getter Chain Resolution

**Problem:** The `ExpressionParser::resolvePropertyReference()` method only tried getter and direct access, missing isser and haser methods.

**Solution:** Updated the resolution order to try all accessor methods before falling back to direct property access:

1. Try getter: `getPropertyName()`
2. Try isser: `isPropertyName()`
3. Try haser: `hasPropertyName()`
4. Direct property access

```php
private function resolvePropertyReference(string $reference, object $object, callable $propertyLoader)
{
    $propertyName = substr($reference, 1);
    $propertyLoader($propertyName);
    
    $reflectionClass = new ReflectionClass($object);
    $ucPropertyName = ucfirst($propertyName);
    
    // 1. Try getter: getPropertyName()
    $getterName = 'get' . $ucPropertyName;
    if ($reflectionClass->hasMethod($getterName)) {
        return $object->$getterName();
    }
    
    // 2. Try isser: isPropertyName()
    $isserName = 'is' . $ucPropertyName;
    if ($reflectionClass->hasMethod($isserName)) {
        return $object->$isserName();
    }
    
    // 3. Try haser: hasPropertyName()
    $haserName = 'has' . $ucPropertyName;
    if ($reflectionClass->hasMethod($haserName)) {
        return $object->$haserName();
    }
    
    // 4. Direct property access
    if ($reflectionClass->hasProperty($propertyName)) {
        $property = $reflectionClass->getProperty($propertyName);
        return $property->getValue($object);
    }
    
    return null;
}
```

## 2. Hook External Service Support

**Status:** Feature already implemented in PR #11.

**Verification:** The `Hook` attribute already has the `class` field, and `LazyLoader::executeHook()` correctly resolves and calls external services via `ServiceResolver`.

**Usage:**

```php
#[Hook(
    name: Hook::AFTER_SET_PROPERTY,
    class: ValidationService::class,  // External service
    method: 'validateEmail',
    args: ['##this', '#email']
)]
private ?string $email = null;
```

When `class` is provided, the hook calls the method on the external service instead of the data object itself.

**Test Coverage:** Added `tests/Integration/HookExternalServiceTest.php` with 3 tests:
- Hook with external service class
- Hook with external service and multiple args
- Hook without external service (uses data object)

## 3. New Needs Attribute

**Purpose:** Specify property dependencies to ensure proper loading order. Properties listed in `Needs` are loaded before the annotated property.

**Implementation:**

```php
#[Attribute(Attribute::TARGET_PROPERTY)]
final class Needs
{
    /**
     * @param string[] $properties List of property names to load first
     */
    public function __construct(
        public readonly array $properties = [],
    ) {}
}
```

**Usage:**

```php
class SomeClass
{
    #[DataSourceRef(id: 'sourceA')]
    private $propA;
    
    #[DataSourceRef(id: 'sourceB')]
    private $propB;

    #[Needs(['propA', 'propB'])]
    #[DataSource(
        class: PersonSource::class,
        method: 'someMethod',
        args: ['#propA', '#propB']  // These will be available
    )]
    private $propC;
}
```

**Behavior:** When loading `propC`:
1. First load `propA` (if not already loaded)
2. Then load `propB` (if not already loaded)
3. Finally load `propC`

**Implementation Details:**
- Added `Needs` attribute class in `src/Attribute/Needs.php`
- Added `readNeeds()` method to `AttributeReader`
- Updated `LazyLoader::loadProperty()` to check for Needs and load dependencies recursively
- Properties already loaded are not reloaded (checked via `$this->loadedProperties`)

**Test Coverage:**
- Unit tests: `tests/Unit/Attribute/NeedsTest.php` (3 tests)
- Integration tests: `tests/Integration/NeedsIntegrationTest.php` (2 tests)
  - Verifies dependencies load in order
  - Verifies already-loaded properties aren't reloaded
