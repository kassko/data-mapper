# Summary: Enablable Attributes & Handle Pattern Refactoring

**Date:** January 4, 2026
**Branch:** `feat_break/code/EnablableAttributes_DesignImprov_More`

## Overview

This session implemented comprehensive improvements to the DataMapper attribute system:

1. **Enablable Attributes**: Added `enabled: bool` parameter to all attributes for dynamic activation/deactivation
2. **Handle Pattern**: Unified `KeepProperty/SkipProperty/KeepAllProperties/SkipAllProperties` into `HandleProperty/HandleAllProperties`
3. **RejectAttributeCascading**: New attribute to control inheritance from parent classes
4. **Parameter Naming**: Renamed `sources` → `items` in DataSourcesStore, `configs` → `items` in PropertyConfigStore
5. **Field Rename**: `keepWhen` → `handleWhen` in Property attribute
6. **DataSourceRef Enhancement**: Added `handleWhen` field for conditional data source resolution

## Changes Summary

### New Attributes Created

| Attribute | Purpose |
|-----------|---------|
| `HandleAllProperties` | Class-level default hydration control (`value: bool`) |
| `HandleProperty` | Property-level inclusion/exclusion with conditional `when` |
| `RejectAttributeCascading` | Prevents inheriting from parent classes |

### Attributes Modified (enabled field added)

All 18 attributes now support `enabled: bool = true`:
- DataSourcesStore, PropertyConfigStore, Property, DataSourceRef
- DataSource, SinglePropDataSource, MultiPropDataSource, PropertyConfig
- Getter, Setter, Needs, Loading, MethodAlias
- CustomHydrator, Context
- PropertySettingHook, PropertyHydratingHook, PropertyInstantiatingHook

### Attributes Deleted

- KeepAllProperties, SkipAllProperties
- KeepProperty, SkipProperty

## Handle Pattern Logic

The new `HandleProperty(value, when)` follows the "SAUF" (except) pattern:

| value | when result | Behavior |
|-------|-------------|----------|
| `true` | `true` | Hydrate property |
| `true` | `false` | Skip (SAUF) |
| `false` | `true` | Skip property |
| `false` | `false` | Hydrate (SAUF) |

## Migration Impact

This is a **breaking change** requiring updates to:
1. All uses of Keep/Skip attributes → Handle pattern
2. Property `keepWhen` → `handleWhen`
3. DataSourcesStore/PropertyConfigStore parameter names

A migration guide is provided in the PR documentation.
