## Technical Approach

### Namespace Strategy

Each test category uses a unique namespace under `Kassko\Sample\`:

- `Kassko\Sample\Hook\` for Hook tests
- `Kassko\Sample\DataSourceStore\` for DataSourceStore tests
- `Kassko\Sample\Hydrator\` for Hydrator unit tests
- etc.

This prevents naming conflicts while keeping the `Kassko\Sample\` convention.

### Fixture Duplication Philosophy

Fixtures are intentionally duplicated across test directories. This approach:

1. Makes each test self-contained and readable
2. Allows fixtures to evolve independently with their tests
3. Eliminates hidden dependencies between tests
4. Makes it clear what each test needs without looking elsewhere
