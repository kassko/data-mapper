# PR-2025_12_26_14_19_29 - DataSourceRef Fallbacks Pattern & Priority-Based Hydration

**Branch:** new-features  
**Status:** In Progress  
**Breaking Changes:** YES (v2.0-alpha)

## Overview

Major refactoring implementing priority-based hydration and modernizing the DataSourceRef pattern.

## Changes Implemented

### 1. DataSourceRef Redesign (BREAKING CHANGE)

**Old Pattern (chain):**
```php
#[DataSourceRef(
    chain: ['sourceA', 'sourceB', 'sourceC'],
    exceptionOnNoValidDataSource: NoValidDataSourceException::class
)]
private ?string $data = null;
```

**New Pattern (fallbacks):**
```php
#[DataSourceRef(
    id: 'sourceA',
    fallbacks: ['sourceB', 'sourceC'],
    exceptionOnNoValidDataSource: NoValidDataSourceException::class
)]
private ?string $data = null;
```

**Provider Pattern (unchanged):**
```php
#[DataSourceRef(providers: ['providerA', 'providerB', 'providerC'])]
private ?array $config = null;
```

**Validation Rules:**
- `id` and `providers` are mutually exclusive
- `fallbacks` can only be used with `id`
- `exceptionOnNoValidDataSource` requires `fallbacks` to be set

### 2. Priority System

Added `priority` field (integer, default: 0) to all data source attributes:
- `DataSource`
- `SinglePropDataSource`
- `MultiPropDataSource`
- `DataSourceRef`

**Priority-Based Hydration Logic:**
1. When hydrating a property, check if it was previously hydrated by another source
2. Compare priorities: incoming source priority vs. current source priority
3. If incoming priority > current priority → override property value
4. If incoming priority ≤ current priority → skip hydration (keep existing value)
5. Track source signatures for debugging/logging

**Implementation Details:**
- Added `propertySourceRegistry` WeakMap to track `property => {source, priority}`
- Added `canHydrateProperty()` method to check priority before hydration
- Added `registerPropertyHydration()` method to register successful hydration
- Added `createSourceSignature()` method to create unique source identifiers

## Migration Guide

**For users upgrading from previous versions:**

### chain → fallbacks

**Before:**
```php
#[DataSourceRef(
    chain: ['primary', 'backup'],
    exceptionOnNoValidDataSource: MyException::class
)]
```

**After:**
```php
#[DataSourceRef(
    id: 'primary',
    fallbacks: ['backup'],
    exceptionOnNoValidDataSource: MyException::class
)]
```

### Using Priorities

```php
// Low priority source - loaded first, can be overridden
#[DataSource(
    class: CacheDataSource::class,
    method: 'getCached',
    priority: 0  // or omit, default is 0
)]
private ?string $name = null;

// High priority source - overrides cached data
#[DataSource(
    class: ApiDataSource::class,
    method: 'getFromApi',
    priority: 10  // higher priority overwrites
)]
private ?string $name = null;
```
