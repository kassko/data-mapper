# PR #15: Verify auto-loading behavior and clarify Needs attribute documentation

**Author:** Copilot  
**Created:** 2025-12-19  
**Merged:** TBD  

---

Verifies and documents the auto-loading behavior for properties passed as arguments, and clarifies the proper use case for the `Needs` attribute with comprehensive tests and updated documentation.

## Summary

This PR addresses a critical understanding gap about when to use the `Needs` attribute versus relying on automatic property loading. The key insight:

- **Properties in args auto-load** - When a property is referenced as `#propX` in a DataSource's `args`, it is automatically loaded BEFORE being passed to the DataSource. No `Needs` attribute is required.
- **Needs is for other cases** - The `Needs` attribute is for when properties must be loaded for reasons OTHER than being passed as arguments, such as when they're used in the getter, validation logic, or hooks.

## 1. Verification of Auto-Loading Behavior

**Status:** ✅ Already implemented and working correctly

**Implementation:** The `ExpressionParser::resolvePropertyReference()` method already calls `$propertyLoader($propertyName)` BEFORE resolving the property value. This ensures properties are loaded when referenced in args.

**How it works:**

1. When a DataSource has `args: ['#propA']`, the ExpressionParser is called to resolve args
2. For each `#propA` reference, `resolvePropertyReference()` is called
3. The method calls `$propertyLoader('propA')` which triggers `LazyLoader::loadProperty()`
4. After loading, the property value is retrieved via getter chain and returned

**Code flow:**
```php
// In ExpressionParser.php
private function resolvePropertyReference(string $reference, object $object, callable $propertyLoader)
{
    $propertyName = substr($reference, 1);
    
    // Auto-load the property if it needs loading
    $propertyLoader($propertyName);  // ← This is the key line
    
    // Then resolve value using getter chain
    // ... getter resolution logic ...
}
```

**Test Coverage:** Added comprehensive tests in `tests/Integration/AutoLoadArgsTest.php`:
- `testPropertyInArgsIsAutoLoadedWithoutNeeds()` - Verifies single property auto-loads
- `testMultiplePropertiesInArgsAutoLoad()` - Verifies multiple properties auto-load

Both tests confirm that:
1. Properties in args load automatically without `Needs`
2. Loading happens in the correct order
3. Each property loads exactly once

## 2. Clarification of Needs Attribute Use Case

**Problem:** Documentation was unclear about when to use `Needs` vs relying on auto-loading.

**Solution:** Updated documentation to clearly distinguish:

### When Auto-Loading Happens (No Needs Required)

Properties referenced as `#propX` in DataSource args are automatically loaded:

```php
#[DataSource(
    class: Service::class,
    method: 'process',
    args: ['#propA', '#propB']  // ← These auto-load
)]
private $result;
```

### When Needs Is Required

Use `Needs` for properties that must be loaded for reasons OTHER than args:

✅ **Properties used in the getter**
```php
#[Needs(['customer', 'discount'])]
#[DataSource(
    class: PriceCalculator::class,
    method: 'calculateTotal',
    args: ['#orderId']  // ← orderId auto-loads
)]
private ?float $finalPrice = null;

public function getFinalPrice(): ?float
{
    $this->loadProperty('finalPrice');
    
    // customer and discount used here - loaded via Needs
    if ($this->customer->isPremium()) {
        return $this->finalPrice * (1 - $this->discount);
    }
    return $this->finalPrice;
}
```

✅ **Properties needed for validation or computation**
```php
#[Needs(['validator'])]
#[DataSource(
    class: Source::class,
    method: 'getData',
    args: ['#id']  // ← id auto-loads
)]
private ?string $data = null;

public function getData(): ?string
{
    $this->loadProperty('data');
    
    // validator used here - loaded via Needs
    if (!$this->validator) {
        throw new \RuntimeException('Validation failed');
    }
    return $this->data;
}
```

❌ **NOT for properties in args** (they auto-load)
```php
// WRONG - propA is in args, auto-loads already
#[Needs(['propA'])]
#[DataSource(args: ['#propA'])]
private $result;

// RIGHT - no Needs needed
#[DataSource(args: ['#propA'])]
private $result;
```

## Key Insights

1. **Auto-loading is already working** - The ExpressionParser has always auto-loaded properties referenced in args since PR #14 (when the propertyLoader callback was added)

2. **Needs serves a different purpose** - It's not about ensuring properties are available for args (that's automatic), it's about ensuring properties are loaded BEFORE the current property for use in getters, validation, etc.

3. **Documentation clarity is crucial** - The previous documentation made it seem like Needs was required for properties in args, which caused confusion about when to use it

## Migration Guide

If you have existing code that uses `Needs` for properties that are ONLY used in args:

```php
// Before (unnecessary Needs)
#[Needs(['propA'])]
#[DataSource(args: ['#propA'])]
private $result;

// After (remove unnecessary Needs)
#[DataSource(args: ['#propA'])]
private $result;
```

This is not a breaking change - the code will continue to work, but the `Needs` is redundant and can be removed for clarity.
