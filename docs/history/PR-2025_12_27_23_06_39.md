# PR-2025_12_27_23_06_39 - DataSourceRef & PropertyConfig Refactoring

## Summary

This PR introduces two major design improvements to the attribute system:

1. **DataSourceRef: `discriminator` → `rule` + `defaultCandidate`**
2. **PropertyCandidates → PropertyConfigStore + Property.configCandidates**

These changes improve the API consistency and add a mandatory default fallback mechanism.

## Breaking Changes ⚠️

**No backward compatibility is provided.** This is an alpha version refactoring.

### DataSourceRef Changes

- Parameter `discriminator` renamed to `rule` in candidates
- New mandatory `defaultCandidate` parameter when using `candidates`
- Both `candidates` and `defaultCandidate` must be present or both absent
- `fallbacks` and `exceptionOnNoValidDataSource` cannot be used with candidates mode

**Before:**
```php
#[DataSourceRef(candidates: [
    ['id' => 'sourceA', 'discriminator' => "expr(context('flag'))"],
    ['id' => 'sourceB', 'discriminator' => 'expr(true)'],
])]
```

**After:**
```php
#[DataSourceRef(
    candidates: [
        ['id' => 'sourceA', 'rule' => "expr(context('flag'))"],
    ],
    defaultCandidate: ['id' => 'sourceB']
)]
```

### PropertyCandidates Replacement

The `PropertyCandidates` and `PropertyCandidate` attributes have been deleted and replaced by:

- **`PropertyConfigStore`**: Class-level attribute storing reusable `PropertyConfig` definitions
- **`PropertyConfig`**: Individual configuration with an ID, class, mapping, etc.
- **`Property.configCandidates`**: Array of `['id' => string, 'rule' => string]`
- **`Property.defaultConfigCandidate`**: Default config ID when no rule matches

**Before:**
```php
#[PropertyCandidates([
    new PropertyCandidate(
        discriminator: "expr(rawDataItemExists('gasolineKind'))",
        property: new Property(class: GasolineCar::class)
    ),
    new PropertyCandidate(
        discriminator: "expr(rawDataItemExists('energyProvider'))",
        property: new Property(class: ElectricCar::class)
    )
])]
private array $cars = [];
```

**After:**
```php
#[PropertyConfigStore([
    new PropertyConfig(id: 'gasolineCar', class: GasolineCar::class),
    new PropertyConfig(id: 'electricCar', class: ElectricCar::class),
])]
class Garage
{
    #[Property(
        configCandidates: [
            ['id' => 'gasolineCar', 'rule' => "expr(rawDataItemExists('gasolineKind'))"],
            ['id' => 'electricCar', 'rule' => "expr(rawDataItemExists('energyProvider'))"],
        ],
        defaultConfigCandidate: 'gasolineCar'
    )]
    private array $cars = [];
}
```

## Migration Guide

### For DataSourceRef candidates

1. Rename `discriminator` to `rule` in all candidate arrays
2. Remove the last `['id' => '...', 'discriminator' => 'expr(true)']` fallback candidate
3. Add `defaultCandidate: ['id' => '...']` with the fallback source ID

### For PropertyCandidates

1. Add `#[PropertyConfigStore([...])]` at class level with all your configs
2. Give each config a unique `id`
3. Replace `#[PropertyCandidates([...])]` with `#[Property(configCandidates: [...], defaultConfigCandidate: '...')]`
4. Rename `discriminator` to `rule` in all candidate arrays
5. Remove `property:` wrapper - reference configs by `id` only

## Rationale

1. **Explicit default**: The `defaultCandidate` pattern ensures there's always a fallback, preventing silent failures
2. **Consistent naming**: `rule` is more descriptive than `discriminator` for conditional expressions
3. **Reusability**: `PropertyConfigStore` allows defining configs once and reusing them
4. **Cleaner syntax**: Referencing configs by ID is more concise than embedding full `Property` objects
