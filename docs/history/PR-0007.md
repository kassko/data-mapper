# PR #7: Implement PSR-11 interface and registry pattern for LazyLoader

**Author:** Kassko 
**Created:** 2025-12-19  
**Merged:** 2025-12-19  

---

Makes `ServiceLocatorInterface` extend PSR-11 `ContainerInterface` and removes the need for `prepare()` calls via a static registry pattern, enabling automatic lazy loading and object serialization.

## Changes

**PSR-11 Interface Compliance**
- `ServiceLocatorInterface` extends `Psr\Container\ContainerInterface`
- Method signatures updated: `$key` → `$id`, return type `string` → `mixed`
- `ArrayServiceLocator` throws proper `NotFoundException` implementing `NotFoundExceptionInterface`
- Constructor default: `array $map = []`

**Registry Pattern**
- Added `LazyLoaderRegistry` with static `set()`/`get()`/`has()`/`clear()` methods
- `LoadableTrait` queries registry instead of storing injected loader
- `DataMapperBuilder::build()` registers LazyLoader globally
- `DataMapper` constructor auto-registers for backward compatibility
- Removed `prepare()` method and loader property injection

**Benefits**
- Objects serializable (no service dependencies)
- Graceful degradation when DataMapper unconfigured
- Simpler API surface

## Usage

**Before:**
```php
$dataMapper = new DataMapper();
$person = new Person(1);
$dataMapper->prepare($person);
$name = $person->getName();
```

**After:**
```php
(new DataMapperBuilder())->build();
$person = new Person(1);
$name = $person->getName();  // Just works
$serialized = serialize($person);  // Now possible
```

Backward compatible: existing `DataMapper` instantiation continues to work.
