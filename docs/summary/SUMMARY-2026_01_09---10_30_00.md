# Work Summary - January 9, 2026

## Overview

This summary documents the implementation of breaking changes for the data-mapper library focused on improving the API semantics, enforcing MultiPropDataSource uniqueness, and implementing exclusive control of DataSource loading via the HandleProperty pattern.

## Completed Tasks

### 1. Renamed `Property::key` to `Property::sourceField`

**Files Modified:**
- [src/Attribute/Property.php](../../src/Attribute/Property.php) - Changed constructor parameter from `key` to `sourceField`
- [src/Loader/Loader.php](../../src/Loader/Loader.php) - Updated `getPropertyNameMapping()` and `mergePropertyConfig()` methods

**Rationale:** The term "key" implied an array key, but future versions will support data sources returning DTOs. The term "sourceField" is more generic and applies to both array keys and DTO properties.

### 2. Renamed `PropertyConfig::key` to `PropertyConfig::sourceField`

**Files Modified:**
- [src/Attribute/PropertyConfig.php](../../src/Attribute/PropertyConfig.php) - Changed constructor parameter from `key` to `sourceField`

### 3. Added MultiPropDataSource Uniqueness Validation

**Files Modified:**
- [src/Validation/MetadataValidator.php](../../src/Validation/MetadataValidator.php) - Added `validateMultiPropDataSourceUniqueness()` method

**New Behavior:**
- Prevents declaring multiple properties with MultiPropDataSource of the same ID
- Prevents declaring multiple properties with DataSourceRef pointing to the same MultiPropDataSource ID
- Validation errors are reported via MetadataValidator

### 4. Implemented HandleProperty Exclusive Control Over DataSource Loading

**Files Modified:**
- [src/Loader/Loader.php](../../src/Loader/Loader.php) - Updated `getHydratableProperties()` and `loadProperty()` methods
- [src/DataCollector/AttributeCascadeCollector.php](../../src/DataCollector/AttributeCascadeCollector.php) - Added `collectSkippedDataSourceProperty()` method
- [src/DataCollector/CascadeEvent.php](../../src/DataCollector/CascadeEvent.php) - Added `TYPE_SKIPPED_DATASOURCE_PROPERTY` constant

**New Behavior:**
- Properties with DataSource/MultiPropDataSource/DataSourceRef attributes are only loaded if authorized by the HandleProperty pattern
- Properties that are skipped due to HandleProperty generate warning logs and profiler events
- The formula for loading is: `enabled && handlePropertyPattern && (matchesDataField || hasMapping) && loadingScope`

### 5. Improved MultiPropDataSource Loading Scope Behavior

**Files Modified:**
- [src/Loader/Loader.php](../../src/Loader/Loader.php) - Updated `filterProperties()` method, added `propertyMatchesDataField()` method

**New Behavior:**
A property can be loaded from a MultiPropDataSource if:
- A: Property is enabled
- B: Property is authorized by HandleProperty pattern
- C: Property name matches a key in the data OR sourceField maps to a key in the data
- D: OR property has a mapping attribute with matching keys in data
- E: Loading scope does not contradict loading this property

## Breaking Changes Summary

| Change | Migration Action |
|--------|------------------|
| `Property::key` → `Property::sourceField` | Replace `key:` with `sourceField:` in Property attributes |
| `PropertyConfig::key` → `PropertyConfig::sourceField` | Replace `key:` with `sourceField:` in PropertyConfig attributes |
| MultiPropDataSource uniqueness | Ensure each MultiPropDataSource ID is used only once per class |
| HandleProperty controls DataSources | Add `#[HandleProperty(value: true)]` to properties with DataSource attributes when using `HandleAllProperties(value: false)` |
